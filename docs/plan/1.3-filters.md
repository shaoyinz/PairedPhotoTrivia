# 1.3 Filters (`filters.py`)

Pure `list[PhotoMeta] -> list[PhotoMeta]`, each rule independently testable and countable
(the report needs to show how many photos each rule dropped).

**Status (2026-10-02):** done — `spike/tests/test_filters.py`, no real library needed. On the
synthetic fixture, `filter a` drops 1 screenshot, 1 no-timestamp row and 3 burst frames;
`filter b` drops nothing and keeps B's GPS-less Tahoe run. The walking skeleton now stops at
§1.4. Real dropped counts arrive with the first on-device export (1.2a's open item) and land in
the §1.8 report.

- [x] Drop screenshots: trust the CSV's `is_screenshot` flag alone. The exporters already set it:
      PhotoKit's `.photoScreenshot` subtype on iOS; on the Mac, osxphotos' `screenshot` flag or a
      PNG with no camera make (`library.py`, since the CSV has no UTI column). *Do not re-derive
      it from `camera_make`: the iOS exporter leaves that empty on every row (1.2a), so "no camera
      make" would drop real photos.*
- [x] Drop photos with no capture timestamp
- [x] Collapse bursts to one representative (prefer `is_burst_pick`, else earliest). *Several
      picks → the earliest pick; ties → smallest `asset_id`. The iOS fetch already returns one
      asset per burst, so this mostly matters for the osxphotos path.*
- [x] Keep no-GPS photos — they are still counted for the ≥ 5 photo rule and for backfill
- [x] Defer dark/blurry filtering (PRD lists it, but it needs pixels; note it for phase 2).
      *Noted under "Open items" in the [plan index](../IMPLEMENTATION_PLAN.md).*

`apply_all` runs screenshots → no timestamp → bursts and counts a photo once, under the first
rule it breaks. Bursts go last so "earliest" compares real timestamps. Every rule keeps input
order.
