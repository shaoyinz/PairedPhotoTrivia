# 1.4 Buckets and matching (`buckets.py`, `matching.py`)

This is the part that mirrors what actually crosses the network, so keep the boundary honest:
`matching.py` may only ever see hashes, never coordinates or timestamps.

**Status (2026-10-02):** done — `spike/tests/test_buckets.py` and `spike/tests/test_matching.py`,
no real library needed. On the synthetic fixture A's 346 kept photos expand to 8,165 hashes, B's
332 give 314 raw ones, and 61 survive. Each side maps those 61 back alone to the same 61 keys
(A: 70 photos, B: 63). Every planted day matches, Monterey through B's single photo. So do
shared-home nights and weekends, which is §1.6's job to remove. The walking skeleton now stops
at §1.5.

- [x] `bucket_key(photo) -> (geohash6, hour_index)` where `hour_index = floor(utc_epoch / 3600)`.
      *Floor, not truncation: a pre-1970 photo at epoch −1 is hour −1. Swift's `/` truncates, so
      the port needs floor division. Geohash cells are half-open (a point on the top edge is in
      the cell above).*
- [x] `salted(key, salt) -> HMAC-SHA256(salt, f"{geohash6}|{hour_index}")`, truncated to 16 bytes.
      *ASCII message bytes. A salt that is not exactly 32 bytes raises. A known-answer test,
      cross-checked against `openssl dgst -mac HMAC`, pins the format for the Swift port.*
- [x] `expand(key) -> set[key]`: the 8 geohash-6 neighbors + self, × hours {h-1, h, h+1}.
      *27 keys normally. The antimeridian wraps; at either pole the row beyond it is skipped, so
      6 cells and 18 keys. Reach is symmetric: b is in `expand(a)` exactly when a is in
      `expand(b)`.*
- [x] **Expand one side only.** Intersect `expand(A)` against raw `B`. Expanding both sides
      roughly triples the effective radius and window, and inflates false matches.
      *A pair always matches when it is less than one cell wide and tall apart and under an hour
      apart. It can match up to two cells and just under two hours apart, never more. Tests show pairs two cells or two hours
      apart that one-sided matching rejects and two-sided would have kept.*
- [x] `match(hashed_expanded_a, hashed_b) -> set[hash]`, then each side maps the surviving
      hashes back to its *own* local photos — exactly what a device can do alone.
      *`buckets.matched_keys(own, matched, salt)`: A passes its expanded keys, B its raw ones,
      and both get the same set back (B's matched cells). `buckets.matched_photos` then picks the
      photos: A's whose neighborhood reaches a matched key, B's whose own key matched. `photoquiz
      match` prints both sides' counts.*
- [x] Salt: 32 random bytes in `data/salt.key`, generated once, shared by both exports (it
      stands in for the salt the two paired devices will hold). *`cli._salt` creates it on first
      use, mode 0600.*
