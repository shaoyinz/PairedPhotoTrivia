# 1.8 Labels and evaluation (`report.py`)

**Status (2026-10-03):** tooling done — `spike/tests/test_report.py`, no real library needed.
`photoquiz sweep` and `photoquiz report` complete the walking skeleton: `make skeleton` now runs
end to end and passes at precision 1 and recall 1. The rest needs the two real exports: labels
written before any output is seen, the report on that data, and defaults picked from its sweep.

On the synthetic fixture, every sweep run but one finds the six planted trips with no split or
merge. The exception is `min_photos = 3`, which lets in the 2 + 2 near-trip: 7 trips, precision
0.86. No run's tails ([§1.7](1.7-trip-assembly.md)) leave a label: 37 tail hours inside, none
outside, at 24 h. At 12 h the night stops Yosemite's tail (17 inside), and with tails off it
covers its first day only. Outside the planned values, a 5 km home city merges Napa and Santa Cruz, and a 12 h silence
cap splits Tahoe. Precision and recall stay at 1 in both cases, and only the split and merge
counts show them. The fixture was built to pass the defaults, so it cannot choose between them.
The defaults stay until the real sweep.

## Order on real data

1. Write `data/labels.csv` from memory, a calendar or the Photos app, **before** running `trips`.
2. `ingest` → `filter` → `buckets` → `match` → `anchors` (check them) → `trips` → `sweep` → `report`.
3. `report` also lists, on the terminal only, what to check by hand: missed, split and merged
   labels, and windows no label covers. Those names and dates never go into the report.

`make skeleton` writes into `data/` as well, but it cannot overwrite real files. `synth` and
`anchors` record a hash of every file they write in `data/generated.json`. They replace a file
only if it is missing, already holds the same bytes, or is still exactly what the pipeline last
wrote there. So a real export copied in, labels written by hand or edited anchors stop the run
at `synth`, with nothing written. Blind labels cannot be redone, so this matters. `--force`
overrides it per command, and `make skeleton DATA=<dir>` runs the skeleton elsewhere. Use a
directory outside the repo: `.gitignore` covers `trips.json` or `spike_report.md` only inside
`data/`.

## Checklist

- [ ] Hand-label trips *before* looking at output, in `data/labels.csv`
      (`label,start_date,end_date,place`) — labeling after seeing results inflates precision
      *Needs the real exports. The format is now enforced: `report` and `sweep` refuse a row with
      the wrong field count, a date that is not yyyy-mm-dd, or an end before the start, and name
      the line. Cells are stripped and blank lines skipped, since the file is typed by hand.
      Dates are UTC and inclusive, so a label runs from start_date 00:00Z to the midnight after
      end_date. West of UTC, a trip's evening falls on the next UTC day, so a label written in
      local dates can miss a trip that ran late.*
- [x] A detected trip is a true positive if it overlaps a labeled trip in time
      *Old-home days ([§1.7](1.7-trip-assembly.md)) are left out before scoring: they are not trips,
      so they are neither true nor false positives, and labels stay trips only. The report counts
      them in a row of their own, and `report` prints the count on the terminal. A labeled trip
      that comes out as old-home days is a missed label, so a wrong past home shows up in recall.
      `evaluate`. Both intervals are half-open: the trip's window, reach included, and the
      label's UTC days. Precision counts detected trips, recall counts labels. With nothing
      detected, precision is 0 rather than undefined, so an empty run fails the gate.*
- [x] Report precision, recall, and separately **split** (n detected : 1 labeled) and **merge**
      (1 detected : n labeled) counts — a merged pair scores fine on precision while being the
      failure most likely to make a quiz round feel wrong
      *A split is a label that two or more detected trips overlap. A merge is a detected trip
      that overlaps two or more labels. Each counts once, however many pieces it has. A label
      found as three trips gives three true positives and one label found, so neither precision
      nor recall moves.*
- [x] Tail hours inside and outside labels ([§1.7](1.7-trip-assembly.md)) — precision cannot see
      a tail that runs past the trip, since the matched part already overlaps the label
      *`evaluate` counts every hour a tail carries a trip, from the matched part to the tail's
      farthest photo, as inside a label or outside every one. The reach beyond that photo is
      left out: west of UTC it crosses a label's UTC midnight on any evening, which would count
      as a tail error. `trips.json` does not record the reach, so `report` assumes the default
      3 h. Hours outside every label are what to look at: a partner who went home and took no
      photo there, or labels written in local dates. The report shows both counts, and the
      sweep shows them per run.*
- [x] GPS coverage: % of photos with coordinates, overall / by year / by camera-vs-imported;
      plus % dropped per filter rule. iOS exports leave `camera_make` empty on every row
      ([§1.2a](1.2-export.md)), which means unknown, not imported — report the split as unavailable
      for those, rather than 0% camera
      *`coverage`, per partner, over the photos the filters kept: overall, by UTC year, camera
      vs imported, and **travel photos**. Travel photos are the ones inside a labeled trip, and
      the tier-2 trigger (< 60%) is about them. They come from labels rather than detected
      trips, because detection needs GPS and would flatter the number. The camera split is
      "unavailable" for an export where no row has a camera make, which is every iOS export.
      Filter drops are shown as a share of the export.*
- [ ] Parameter sweep over gap hours, geohash precision (5/6/7), min photos — pick defaults
      from the sweep and record them. Since [§1.7](1.7-trip-assembly.md), also the home-city radius (15 / 25 / 50 km),
      the silence cap (24 / 72 / 168 h) and the tail gap (0 / 12 / 24 / 48 / 72 h); split and
      merge counts are what move with the first two, tail hours with the third
      *The sweep is built. Picking and recording defaults waits for the real run. `photoquiz
      sweep` varies one parameter at a time around the defaults: gap 6 / 12 / 24 h, geohash
      5 / 6 / 7, min photos 3 / 5 / 8, home city 15 / 25 / 50 km, silence cap 24 / 72 / 168 h,
      tail gap 0 (no tails) / 12 / 24 / 48 / 72 h.
      The home-city radius and the silence cap interact: each can end a trip the other lets run,
      and a 5 km city merges Napa and Santa Cruz only from a 72 h cap. So that pair also runs
      over all nine of its value pairs, which adds four runs. That is 19 runs instead of the full
      grid's 1,215. On the fixture the four new corners match the defaults. Gaps start at 6 because
      the 3 h reach must be at most half the gap. Each run takes the pipeline's own path (A
      expanded, B raw, salted, intersected, mapped back), and matching is redone once per geohash
      precision. `bucket_key` and `own_keys` take a `precision` argument for this, defaulting to
      6. The sweep writes `data/sweep.json`. `report` renders it unless it is older than any of
      its inputs (labels, anchors, filtered photos, salt), so a sweep of other data, such as the
      synthetic run, never lands in a real report. The best run is picked as follows. Runs past
      the precision gate beat every run short of it. Among them, recall ranks first, then the
      fewest merges, the fewest splits and precision. If no run passes, precision ranks first
      instead of recall, so a run that finds every trip at 40% precision cannot win. Ties keep
      the defaults. When either partner has a past home ([§1.5](1.5-anchors.md)), `sweep_cmd` adds
      one run with `past_homes=false` (the anchors alone), so the report shows what the home
      history changes. The synthetic libraries have none, so their sweep stays at 19 runs.
      Tail hours do not rank runs: a shorter tail cuts hours inside labels along with those
      outside, so `best` would always pick no tails. Choose `tail_gap_hours` from the report's
      tail column by hand.*
- [ ] Write `data/spike_report.md` (gitignored; the numbers, not the raw rows, go in the PR)
      *The writer is built and waits for real data. `photoquiz report` writes the gate
      (precision ≥ 90%, travel-photo coverage against 60%), trips against labels, coverage,
      filter drops and the sweep. It holds numbers only, with no label names, places,
      geohashes, dates or rows, and a test enforces that. `--min-precision 0.9` makes it exit 1
      below the gate.*
