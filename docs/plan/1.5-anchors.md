# 1.5 Anchors: home and work (`anchors.py`)

Needs *local* hours, which is why the export keeps `tz_offset_s` alongside UTC.

**Status (2026-10-02):** done — `spike/tests/test_anchors.py`, no real library needed. On the
synthetic fixture A's home is 9q8yvf1 (17 nights) and work 9q8yyxr (27 weekdays); B's home is
9q8yvcc (19 nights) and work 9q9jh0m (24 weekdays). All four land within 80 m of the planted spots (56–75 m).
The two homes fall in neighboring cells because the planted home sits on a cell edge, so §1.6 must
compare homes by distance, as planned, not by geohash. The walking skeleton now stops at §1.7
(`trips` calls `sessionize` first). Real support counts arrive with the first on-device export.

- [x] Home = the geohash-7 seen on the most **distinct nights** among photos with local hour in
      [00:00, 06:00). *Distinct local days, not photos: one night out with 40 photos must not
      outvote six ordinary nights at home. Ties → more photos, then smallest geohash, so input
      order never matters. The position is the mean of that cell's photos.*
- [x] Work = the geohash-7 seen on the most **distinct weekdays** among photos with local hour in
      [10:00, 16:00) on Mon–Fri. *Days again, so a week of weekday vacation photos cannot become
      "work". Weekday is local too: 15:00 Sunday in Hawaii is Monday in UTC and still the weekend.
      No such photos → `work = None` (the buffer becomes a disc around home).*
- [x] Local time is `utc_epoch + tz_offset_s` per photo, so DST and travel need no special case.
      Photos with no GPS or no time zone are skipped. *Floor division and modulo (hour, day,
      `weekday = (day + 3) % 7`), so the Swift port needs the floor versions, as in §1.4.*
- [x] Window: last 90 days of the export, `[latest photo − 90 d, latest photo]`, both ends
      inclusive. If that is too sparse, widen with `--window-days` and say so in the report.
      *No night photo at all → `NoNightPhotosError`, and the CLI says to widen or write the file
      by hand. A weak anchor is still written: `home_nights` / `work_days` hold the support, and
      the CLI warns below `MIN_SUPPORT_DAYS = 5` (a guess until real libraries say otherwise).*
- [x] Emit a `data/anchors_<person>.toml` the user edits by hand — this is the stand-in for the
      in-app confirm/edit screen, and hand-editing it is expected, not a fallback. *Because edits
      are expected, `anchors` refuses to overwrite a file edited by hand without `--force`. It
      can tell, because it records a hash of what it wrote in `data/generated.json`
      ([§1.8](1.8-evaluation.md)). An unedited file is replaced freely, so the Makefile skeleton
      no longer passes `--force`.*
