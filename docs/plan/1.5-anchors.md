# 1.5 Anchors: home and work (`anchors.py`)

Needs *local* hours, which is why the export keeps `tz_offset_s` alongside UTC.

**Status (2026-10-02):** done — `spike/tests/test_anchors.py`, no real library needed. On the
synthetic fixture A's home is 9q8yvf1 (17 nights) and work 9q8yyxr (27 weekdays); B's home is
9q8yvcc (19 nights) and work 9q9jh0m (24 weekdays). All four land within 80 m of the planted spots (56–75 m).
The two homes fall in neighboring cells because the planted home sits on a cell edge, so §1.6 must
compare homes by distance, as planned, not by geohash. The walking skeleton now stops at §1.7
(`trips` calls `sessionize` first). Real support counts arrive with the first on-device export.

- [x] Home = the geohash-7 seen on the most **distinct nights** among photos with local hour in
      [00:00, 06:00). *Distinct local days, not photos: one night out with 40 photos must not
      outvote six ordinary nights at home. Ties → more photos, then smallest geohash, so input
      order never matters. The position is the mean of that cell's photos.*
- [x] Work = the geohash-7 seen on the most **distinct weekdays** among photos with local hour in
      [10:00, 16:00) on Mon–Fri. *Days again, so a week of weekday vacation photos cannot become
      "work". Weekday is local too: 15:00 Sunday in Hawaii is Monday in UTC and still the weekend.
      No such photos → `work = None` (the buffer becomes a disc around home).*
- [x] Local time is `utc_epoch + tz_offset_s` per photo, so DST and travel need no special case.
      Photos with no GPS or no time zone are skipped. *Floor division and modulo (hour, day,
      `weekday = (day + 3) % 7`), so the Swift port needs the floor versions, as in §1.4.*
- [x] Window: last 90 days of the export, `[latest photo − 90 d, latest photo]`, both ends
      inclusive. If that is too sparse, widen with `--window-days` and say so in the report.
      *No night photo at all → `NoNightPhotosError`, and the CLI says to widen or write the file
      by hand. A weak anchor is still written: `home_nights` / `work_days` hold the support, and
      the CLI warns below `MIN_SUPPORT_DAYS = 5` (a guess until real libraries say otherwise).*
- [x] Emit a `data/anchors_<person>.toml` the user edits by hand — this is the stand-in for the
      in-app confirm/edit screen, and hand-editing it is expected, not a fallback. *Because edits
      are expected, `anchors` refuses to overwrite a file edited by hand without `--force`. It
      can tell, because it records a hash of what it wrote in `data/generated.json`
      ([§1.8](1.8-evaluation.md)). An unedited file is replaced freely, so the Makefile skeleton
      no longer passes `--force`.*

## Home history (2026-10-04)

**Status (2026-10-04):** done — `spike/tests/test_anchors.py`, no real library needed. The user
confirms the current home only and is never asked about past ones (PRD), so past homes are
inferred. [§1.7](1.7-trip-assembly.md) judges each hour against the homes the two partners had then.

Why: a real library spans years and often more than one home, sometimes in another time zone.
Judged against today's home alone, everyday life in the old city reads as away: if both partners
lived there, every ordinary weekend becomes a trip.

Real-data finding: the first real library has far fewer nights with a located photo between 00:00
and 06:00 local than evenings with one between 20:00 and 06:00. At 00:00–06:00 the history finds
nothing; at 20:00–06:00 it finds the past homes and dates the moves plausibly. The current home,
still voted at 00:00–06:00 over 90 days, can rest on a single night there and land on the old
home, so that export's anchors file must be set by hand (an open item in the [plan index](../IMPLEMENTATION_PLAN.md)).

- [x] `home_eras(ps, current, now_utc=...) -> list[Era]`, oldest first, the last one always the
      anchors file's home. *One vote like `infer_anchors` every 30 days back from the latest
      photo, each over the evenings within ±90 days (`EVENING_HOURS`, local [20:00, 06:00)), and
      `MIN_SUPPORT_DAYS` of them to count. A winner within `MOVE_KM` (5 km, the buffer) of the
      current home is the current home, so a home typed in as a zip code's center still matches,
      and a move inside the buffer is no move. Anywhere else must win 3 votes in a row (votes
      without a winner skipped) to be a past home. With regular photos at home, a month away
      cannot. Living at the current home earlier, then moving back, gives it an era of its own.*
- [x] Date each move. *`_moved_at`: the boundary that best splits the nights near the old home
      (before) from those near the new one (after), over the two votes' windows. A clean move gives
      a range from just after the last night at the old home to the first night at the new one; the
      middle is taken. A move too recent to win any vote (the anchors file says new home, the
      evenings say old) is still dated this way, after the last vote.*
- [x] A past home's position and work are voted again over its own era, so a long era gets a
      firm position and its own commute buffer. `Era.nights` carries the support, as
      `home_nights` does.
- [x] A single era means no move: `assemble` then behaves exactly as with the anchors alone, which
      is the case for both synthetic libraries.
- [x] Shown on the terminal only, by `photoquiz trips` (dates and evening counts, no places).
      Never written to a file: it is recomputed from the photos and the anchors file each run.
