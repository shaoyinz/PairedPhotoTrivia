# 1.2 Export

Two paths, one CSV schema, so the Python side has a single reader either way:

```
asset_id,utc_epoch,tz_offset_s,lat,lon,is_screenshot,burst_id,is_burst_pick,
camera_make,camera_model,width,height
```

`asset_id` is a local identifier only — it never leaves the device in phase 2, and in the spike
it exists so a detected trip can be traced back to real photos while hand-checking. Empty
`lat`/`lon` means no GPS, which is a measurement, not a defect: it feeds the coverage report.

## 1.2a iOS exporter — primary path (`ios/MetadataExport/`)

A deliberately small SwiftUI app each partner runs on their own iPhone. One screen, one button,
one share sheet.

**Status (2026-10-01):** not started. Prerequisite met: Xcode 27.0 with the iOS 27.0 SDK is
installed.

- [ ] Request `PHPhotoLibrary` read authorization, handling `.limited` (ask for full access
      here; a limited selection makes coverage numbers meaningless, and the real app needs the
      limited path tested anyway — note the behavior for phase 2)
- [ ] Enumerate `PHAsset` with `PHFetchOptions`, `mediaType == .image`, no sorting
- [ ] Per asset: `localIdentifier`, `creationDate` → UTC epoch, the asset's
      timezone offset for local-hour reasoning ([§1.5](1.5-anchors.md)), `location?.coordinate`,
      `mediaSubtypes.contains(.photoScreenshot)`, `burstIdentifier`,
      `representsBurst`, `pixelWidth`/`pixelHeight`
- [ ] Camera make/model via `PHAssetResource` / `CGImageSource` metadata — only if it is cheap;
      it is used to split coverage by camera-vs-imported, so drop the column rather than make
      the export slow
- [ ] Stream rows to a CSV in the app's temp directory; show a progress count (expect tens of
      thousands of assets)
- [ ] Export via share sheet (AirDrop to the Mac). Never fetch image data — metadata only, so
      the app works with photos that live only in iCloud
- [ ] Build check: run on device, confirm the row count matches Photos' own album count

Distribution: a free personal team sideload from Xcode works and expires after 7 days, which is
fine for a one-time export. A remote partner needs TestFlight, or a screen-share walkthrough of
the Xcode build on their own Mac if they have one.

## 1.2b osxphotos — alternative where a synced Mac library exists

- [ ] `photoquiz ingest --person a --library <path> --out data/a_photos.parquet`, pulling
      `uuid`, `date`, `tzoffset`, `latitude`, `longitude`, `screenshot`/`uti`, `burst`,
      `burst_selected`, `original_filename`, `exif.camera_make`/`model`, `width`, `height`
- [ ] Emits the same CSV schema as 1.2a, so the two paths are interchangeable
- [ ] Requires iCloud Photos enabled on that Mac and Full Disk Access for the terminal.
      Metadata syncs in full even with "Optimize Mac Storage" on; the spike never needs
      original pixels

## 1.2c Ingest (`ingest.py`)

- [x] `photoquiz ingest --person a --csv <path> --out data/a_photos.parquet`
- [x] Validate the schema, report row count, date range, and how many rows lack GPS
- [x] Store timestamps as UTC epoch seconds plus a separate `tz_offset_s` column
- [x] No image data, no thumbnails, no file copies — at any stage
